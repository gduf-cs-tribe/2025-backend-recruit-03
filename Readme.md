- https://github.com/vuejs/vue

## 提交方式

1. Git 仓库地址，仓库内容包括：
   1. **项目完整源代码**

   2. README.md 文件：使用 Markdown 语法书写的项目介绍文档，内容包括:
      1. 项目介绍
      2. 项目使用的语言，用到了该语言的什么语法、特性等
      3. 完成的功能

      注意：
      1. README.md 中的图片一定要确保可以被访问到，不要出现图片路径是本地路径这种低级错误。建议在仓库中开一个文件夹（比如 `assets` 或 `src`）来放置所有图片。
      2. 请确保你的仓库被设置为 **public**, 以便我们访问你的仓库。（gitee 的仓库默认为 private，记得修改）
      3. 允许使用 Github/Gitee 以外的 Git 托管平台，比如 GitLab。自搭建的 Git 托管平台也是被允许的（如果你有这个实力）

2. 请在第三轮考核截止日期之前，将仓库地址通过问卷的方式提交给我们。
   1. 提交地址：[第三轮考核信息收集](https://fcnkfgz1xonr.feishu.cn/share/base/form/shrcnNjVSGlUOVBwXpwCTuI1XDg)
   2. 提交内容：
      1. 你的仓库地址，例如: `https://github.com/username/yourRepositorieName` 或 `https://gitee.com/username/yourRepositorieName` 。注意将仓库权限设置为 public，将提交的代码放在main/master 分支
      2. 另外有一个想对我们说的话部分：你可以谈谈，项目的设计思路、过程中遇到的问题、一些心得体会、对爪哇部落的印象等，都可以写到这部分。
      3. 问卷中将收集你的联系方式，请一定要认真填写，确保我们可以联系到你，以进行接下来的面试。

## 评分细则

考核结束后，我们会在一周内对你的仓库实现进行评分并给出反馈意见。所有反馈意见遵循以下格式：

1. **Summary/概述:** 简要客观总结仓库做了什么，用了何种技术栈？

2. **Strengths/优点:** Reviewer 列出仓库的主要优势，包括但不限于功能、代码风格、文档健全性

3. **Weaknesses/缺点:** Reviewer 列出仓库的缺点列表，包括但不限于功能缺失、环境搭建困难

4. **Suggestions/修改建议:** 针对上述缺点给出的建议，这个建议可以不局限于仓库本身，也可聚焦于个人改进

5. **Questions for Authors/给作者的问题:** （可选）Reviwer 可以按需要提出对仓库具体实现细节的疑问，作者拥有是否选择回答的权利，回答结果可能会影响最终评分

6. **Overall Assessment/总体评分: 满分 10 分，6 分及格。当且仅当达到及格线及以上分数时才会获得面试资格。**评分细节如下：
   - **Core features/核心功能完成度:** (4分) 是否按要求完成了所有必须的功能？（若仓库无法正常运行此处会酌情扣分）
   - **Extra features/可选功能完成度:** (2分) 是否完成了两个及以上的可选功能？
   - **Documentation completeness/文档完备度:** (2分) 文档是否齐全？需要覆盖仓库内容概述、技术栈使用情况、环境搭建指南、测试指南等内容
   - **Core Style/代码风格:** 代码结构清晰，文件模块按功能分区、函数文档齐备、变量命名清晰(1分); 是否遵循了所属语言的代码风格？（参考上面的代码风格指南一节，例如：Python 是否使用了类型注解？Java 是否正确使用了 JavaDoc？是否有效控制了代码缩进？）(1分)

所有 Feedback 将以邮件的形式提供，请务必准确填写邮件地址并时常检查垃圾箱。

对于 Questions for Authors 作者拥有是否选择回答的权利，回答结果可能会影响最终评分。已被回答的题目一般不会出现在面试题目中，除非 Reviwer 对该回答仍然存在疑问需要作者进一步澄清。
